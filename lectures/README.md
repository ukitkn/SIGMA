# SIGMA execution-explanation presentation

Live page: <https://ukitkn.github.io/SIGMA/>

The presentation is designed for ten minutes of oral explanation while stepping
through five selected computational states. It does not replay the full training
trace. The audience sees short What / Changes / Why explanations, computed teaching
outputs and figures, plus a separate summary of archived report results. The full
spoken script is in [PRESENTER_NOTES.md](PRESENTER_NOTES.md),
outside the page. A video is optional under the assignment.

| Time | Selected state | Repository implementation |
| --- | --- | --- |
| 0:00–2:30 | Healthcare problem, motivation and approach | Problem and pipeline overview |
| 2:30–3:40 | Physical and communication graphs | `sigma.graphs.knn_graph`, `build_ccc_graph` |
| 3:40–5:05 | Base embedding, dual GCNs and concat fusion | `sigma.model.SigmaModel.forward` |
| 5:05–6:30 | Expression / CCC decoding and one gradient update | `expression_decoder`, `ccc_logits`, PyTorch losses and Adam |
| 6:30–7:35 | Soft clustering and separate marker annotation | `student_t_assignments`, `sigma.analysis._annotate_compartments` |
| 7:35–8:45 | Rooted DPT and spatial field | `sigma.analysis._trajectory`, `_spatial_field` |
| 8:45–10:00 | Archived result and healthcare interpretation | Report benchmark / ablation tables in `evidence/` |

## Running and presenting

Use Python 3.11+ and install from the repository root:

```bash
python -m pip install -e '.[lectrace]'
lectrace serve lectures/01_sigma_execution.py
```

On the website, use the forward/back arrows to step through the selected code;
`F` enters fullscreen and `E` toggles the variable panel. Spend the suggested time
discussing each state rather than assigning equal time to every click. The webpage
contains a prerecorded execution trace generated by running the Python script
during the build; the viewer does not train a model in the teacher's browser.

## Executed teaching configuration

- 60 synthetic spots on a 6 × 10 grid; the small gene panel retains all its genes.
- Library-total normalization to 10,000 and `log1p`; full expression is retained.
- Physical kNN: coordinate-only, k=8; expression kNN: 15; teaching LR pair: CXCL12 / CXCR4. The report describes H&E morphology in the physical view, but the historical morphology extractor was unavailable and is not used in this teaching example.
- CCC: spatial candidates, receptor-shuffle z-scores with 30 permutations, top-k 8,
  and symmetric edges. This is the repository's LR graph builder, not the full
  CellPhoneDB statistical workflow or a test of causal signaling.
- Three residual GCN layers with LayerNorm; hidden width 16, latent width 8,
  dropout 0.2, three clusters, concat + Linear + ReLU fusion. JK is disabled in
  the teaching configuration; the report does not specify the historical JK
  operator. No H&E features are used in this executable example.
- 80 training epochs execute through `sigma.model.train_model`, with the same loss
  families as the repository. The loop is omitted from the presentation trace.
- One additional visible Adam update uses only the expression and CCC terms,
  weighted 1.5 and 0.1. It uses all distinct unordered spot pairs for a stable
  before/after teaching comparison; the full trainer instead samples graph edges.
  Evaluation mode removes dropout and VAE sampling for that comparison while
  retaining autograd.
- Marker annotation is computed from expression separately from learned clusters.
  A soft cluster assignment is not a tumor probability or a clinical risk.
- For the clustering checkpoint, the repository's KMeans initializer places three
  centers on the current learned embedding after the short training run. This
  deliberately demonstrates initialization followed by Student-t assignment;
  the full trainer normally initializes centers before its optimization loop.
- DPT uses the learned embedding and the current implementation's global,
  spot-level marker-guided root. Tumor-only Leiden clustering is a separate full
  pipeline analysis and is not demonstrated here. The report's state-level root
  description is not silently substituted for this executable behavior.
- Gaussian field: 24 × 24 grid, 20 neighbors, bandwidth 120 coordinate units.
  The field uses DPT directly; it does not pass through a one-dimensional moving
  average. Displayed arrows equal `gradient(P) = -gradient(1-P)`.

These small settings make the neural computation inspectable. They are not the
historical configuration or checkpoints that produced the report's archived benchmark.
The hand-written attention approximation and marker-mixture ranking have been
replaced with calls to the reconstructed implementation.

## Evidence and build checks

The conclusion reads the archived benchmark and ablation CSV tables directly.
Their provenance and metric caveats are documented in [evidence/README.md](evidence/README.md).
No teaching value is substituted into these tables.

```bash
lectrace build lectures/01_sigma_execution.py --no-incremental
python scripts/verify_lecture.py
```

The build checks fusion consistency, normalized soft assignments, a real parameter
update, and finite DPT without invoking the marker-rank fallback. The site verifier
also rejects a trace with an execution error: LecTrace can otherwise serialize an
exception into a trace without failing the build process.
